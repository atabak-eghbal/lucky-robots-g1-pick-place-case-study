Executive summary

This submission converts the original manual keyboard-controlled MuJoCo demo for the Unitree G1 humanoid into an autonomous pick-and-place controller. The primary deliverable is the ground-truth FSM baseline (GT FSM): a 12-state finite-state machine that coordinates the walker and right-reacher ONNX policies, attaches objects kinematically, and completes the end-to-end pick-and-place sequence in simulation. A Visual Oracle perception extension is designed at the architectural level and documented as a separate appendix; it is not implemented in this submission.

The GT FSM baseline is scoped as a debuggable baseline, not a production-grade controller. Every threshold and timeout is derived from a development-log measurement. Known caveats — simulation-only, kinematic attachment, no post-release programmatic confirmation — are stated explicitly and are not suppressed.

The report distinguishes four layers throughout: the original manual baseline, the GT FSM baseline, the architectural Visual Oracle, and the future research roadmap. Claims carry an explicit evidence status; the legend is defined below and applied in the Results appendix.

Contribution statement

What changed from the manual baseline

The challenge repository shipped a keyboard-controlled MuJoCo demo. This submission replaces manual input with a 12-state FSM that drives locomotion, arm reaching, kinematic grasp attachment, transport, and placement without human intervention.

What the GT FSM baseline does

The autonomous controller walks the robot to the source table, positions the arm with the always-on right reacher, attaches the cylinder kinematically once within grasp range, lifts and transports it to the target table, and releases it. Policy coordination choices — always-on reacher requirement, double-normalization fix, empirical accuracy-floor thresholds — are derived from development logs and are described in the Lessons appendix.

What is intentionally limited

  • Grasping is kinematic attachment, not physical finger contact.
  • Post-release on-table confirmation is not validated programmatically.
  • The Visual Oracle is an architectural design; it is not implemented in this submission.
  • All results are simulation-only in MuJoCo; no hardware transfer has been attempted.

What was built

The starting point was the manual keyboard-controlled MuJoCo demo for the Unitree G1 humanoid. The submission converts that demo into an autonomous pick-and-place controller using an explicit 12-state finite-state machine, a kinematic grasp backend, and shared locomotion and manipulation ONNX policies.

The primary deliverable is the GT FSM baseline (Steps 1–10). It is intentionally scoped as a debuggable baseline. Every threshold and timeout is backed by a log observation. A Visual Oracle perception extension is designed at the architectural level; its implementation status is described on the Visual Oracle page.

The end-to-end sequence completed in simulation: the robot settled, approached the source table, hovered and descended to the cylinder, attached it kinematically, lifted and transported it, lowered it above the target surface, and released it. Placement was visually successful in simulation; post-release settling validation has a known caveat described in Results.

Architecture at a glance

The runtime separates orchestration, policy logic, controller synthesis, grasp handling, and validation scripts so each layer can be instrumented and tested in isolation.

Why this approach

The GT FSM baseline was scoped to address each evaluation criterion directly:

  • Decomposition: Five narrow, testable modules — perception, locomotion, manipulation, grasp, sequencing — communicate through explicit interfaces. Each can be instrumented, tuned, and swapped independently without touching the rest of the stack.
  • Methodological reasoning: Thresholds are derived from development-log measurements (reacher accuracy floor, kinematic attach distance) rather than copied from defaults or guessed. Failures were reproduced, understood, and fixed.
  • Adaptability: Each FSM state exposes a clean extension point. Replacing the ground-truth source pose with a Visual Oracle observation requires changing one function; the rest of the sequencing logic is unchanged.
  • Technical depth: Non-obvious policy interactions are surfaced: the always-on reacher requirement (keeps arm joints inside the training distribution), the double-normalization bug (raw observations must bypass the walker's internal normalizer), and the target-side false-positive guard (world proximity and yaw gating added after reach-window checks alone produced false positives).
  • Communication: The report consistently distinguishes the manual baseline, the GT FSM baseline, the architectural Visual Oracle, and the future roadmap. Simulation caveats are never suppressed.

Key evidence from development logs

  • Headless smoke test passed: scene, cameras, bodies, sites, joints, and ONNX policy warmups all verified.
  • Walker double-normalization bug identified and fixed: raw observations must be passed directly to the walker ONNX policy.
  • Always-on reacher requirement: the right reacher must run unconditionally to keep arm joints inside the training distribution.
  • Empirical reacher accuracy floor: radial error plateaued around 12–13 cm; thresholds and timeouts were set around this floor.
  • Kinematic attach distance: 0.128 m measured in the reference run (snap_offset 0.030 m).
  • Target-side false-positive validation bug: reach-window checks alone produced false positives; world proximity and yaw gating were added.
