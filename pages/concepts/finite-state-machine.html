Finite-State Machine

A finite-state machine breaks the robot task into named phases with explicit transitions.

What it means

An FSM represents behavior as states and transition rules. At any moment, the robot is in one state, such as APPROACH_SOURCE or CLOSE_GRIP, and the code decides when to move to the next state.

Why it matters

For robotics tasks, FSMs are useful when behavior needs to be inspectable and recoverable. They make it clear whether a failure happened during navigation, reaching, grasping, transport, or release.

How it appears in this repo

The FSM baseline uses explicit phases for walking, reaching, grasping, and placing. 

SETTLE
APPROACH_SOURCE
HOVER_SOURCE
DESCEND_SOURCE
CLOSE_GRIP
LIFT_SOURCE
APPROACH_TARGET
LOWER_TARGET
OPEN_GRIP
RETRACT
DONE

Each state emits high-level commands instead of direct actuator targets.

Design implications

  • Easier debugging than end-to-end policies.
  • Clear timeout and debounce rules.
  • Easier to add logs and safety checks.
  • More hand-tuned than learned end-to-end behavior.

Common failure modes or misunderstandings

  • Too many magic thresholds.
  • Transitions that fire too early.
  • States that never exit because the robot asymptotes near a target.
  • Success checks that happen before the object settles.
