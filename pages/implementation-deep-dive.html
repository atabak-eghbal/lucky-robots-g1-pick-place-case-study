Implementation Deep Dive: Step 1–10 Ground-Truth FSM Baseline

This section walks through the implementation that converted the original manual MuJoCo demo into a modular autonomous FSM baseline. The code is organized around runtime orchestration, a policy contract, a walker/reacher controller, an explicit FSM, a kinematic grasp backend, and headless tests.

How to read this section

  • Large code snippets are intentionally excerpted.
  • Omitted lines are described in prose rather than pasted in full.
  • The goal is to explain responsibility boundaries, not duplicate the full repo.

03 — Policy Contract policies/base.py

The policy contract is a frozen command packet that keeps policies from mutating controller state directly. 

WalkCommand = tuple[float, float, float]
ReachTarget = tuple[float, float, float]


@dataclass(frozen=True)
class PolicyOutput:
  """High-level command output from a policy step.

  walk_cmd: (lin_vel_x, lin_vel_y, ang_vel_z)
  reach_target: (x, y, z) target coordinates in pelvis frame
  reach_active: True to run the right-arm reacher ONNX overlay
  grip_closed: True when the right-hand grip should be closed
  """

  walk_cmd: WalkCommand
  reach_target: ReachTarget
  grip_closed: bool
  reach_active: bool = False


class BasePolicy(ABC):
  """Abstract interface for policies that emit high-level commands."""

  def handle_key(self, keycode: int) -> None:
    """Optional keyboard hook for interactive policies."""
    pass

  @abstractmethod
  def step(self) -> PolicyOutput:
    """Return the latest policy output."""

What this block does

Defines PolicyOutput as a frozen command packet: walk_cmd is body velocity intent, reach_target is in pelvis frame, and grip_closed stays at the policy level for explicit sequencing.

Why this design matters

Frozen outputs keep commands immutable, and BasePolicy lets keyboard and FSM policies share the same runtime path.

What is intentionally omitted

Policy-specific state machines and interactive keyboard bindings.

class KeyboardPolicy(BasePolicy):

05 — FSM Adapter policies/fsm.py

FSMPolicy adapts the core FSM outputs into controller fields and guards grip logic when the kinematic grasp backend is attached. 

_RELEASE_STATES = frozenset({
    FSMState.OPEN_GRIP,
    FSMState.RETRACT,
    FSMState.DONE,
})


class FSMPolicy(BasePolicy):
    def __init__(self, controller, grasp_backend=None):
        self._controller = controller
        self._grasp_backend = grasp_backend
        self._fsm = FSMCore(controller.model, controller.data)

    def step(self) -> PolicyOutput:
        attached = (
            self._grasp_backend.attached
            if self._grasp_backend is not None
            else False
        )

        out = self._fsm.tick(attached=attached)

        self._controller.lin_vel_x, self._controller.lin_vel_y, self._controller.ang_vel_z = out.walk_cmd
        self._controller.reach_target[:] = out.reach_target
        self._controller.reach_active = out.reach_active
        self._controller.grip_closed = self._close_grip_command(out)

        return out
def _close_grip_command(self, out: PolicyOutput) -> bool:
    if self._grasp_backend is None:
        return out.grip_closed

    if self._fsm.state in _RELEASE_STATES:
        return out.grip_closed

    if self._grasp_backend.attached:
        return True

    return out.grip_closed

What this block does

Bridges FSM outputs into controller fields and protects the grip command.

Why this design matters

The release bug fix preserves intentional drops while preventing accidental releases.

What is intentionally omitted

FSM state machine internals and transition guards.

06 — FSM Brain policies/fsm_core.py

FSMCore is the brain. It reads MuJoCo state, computes geometry, and emits PolicyOutput commands instead of actuator targets. 

class FSMState(Enum):
    SETTLE = auto()
    APPROACH_SOURCE = auto()
    HOVER_SOURCE = auto()
    DESCEND_SOURCE = auto()
    CLOSE_GRIP = auto()
    LIFT_SOURCE = auto()
    APPROACH_TARGET = auto()
    HOVER_TARGET = auto()
    LOWER_TARGET = auto()
    OPEN_GRIP = auto()
    RETRACT = auto()
    DONE = auto()
def tick(self, attached: bool = False) -> PolicyOutput:
    self._tick_total += 1
    self._tick_state += 1
    self._attached = attached

    if self.state == FSMState.SETTLE:
        return self._settle()
    if self.state == FSMState.APPROACH_SOURCE:
        return self._approach_source()
    if self.state == FSMState.HOVER_SOURCE:
        return self._hover_source()
    ...

What this block does

Defines explicit states and dispatches to per-state handlers on every tick.

Why this design matters

Timeouts exist for every state because learned policies can asymptote rather than converge.

What is intentionally omitted

Detailed per-state geometry helpers and transition thresholds.

The source approach uses a staircase velocity schedule after proportional control overshot the reach window.

wz = float(np.clip(K_WZ * heading, -WZ_CAP, WZ_CAP))

What this block does

Modulates forward speed based on distance while correcting lateral drift and yaw.

Why this design matters

Staircase scheduling keeps speed high far away and slows near the reach boundary.

What is intentionally omitted

Debounce counters and the _transition() call that fires when the cylinder stays inside the reach window for enough ticks.

08 — Hover, Descend, Close-Grip, Lift policies/fsm_core.py

These helpers convert world-frame target points into pelvis-frame reach commands for the right arm. This is the coordinate-frame heart of the reacher. 

def _palm_world(self):
    return self._data.site_xpos[self._palm_id].copy()

def _table_surface_z(self):
    return (
        self._data.geom_xpos[self._tbl_geom_id][2]
        + self._model.geom_size[self._tbl_geom_id][2]
    )

def _source_hover_world(self):
    cyl = self._cylinder_world()
    return np.array([cyl[0], cyl[1], self._table_surface_z() + 0.18])

def _source_grasp_world(self):
    cyl = self._cylinder_world()
    return np.array([cyl[0], cyl[1], self._table_surface_z() + 0.06])
def _reach_from_world(self, world_point, right_bias=-0.08):
    pos, quat = self._pelvis_pose()
    local = self._world_to_pelvis(pos, quat, world_point).copy()
    local[1] = min(local[1], right_bias)
    return self._clip_reach_target(local)

What this block does

HOVER_SOURCE targets table_z + 0.18 m, DESCEND_SOURCE targets table_z + 0.06 m, CLOSE_GRIP waits for attachment, and LIFT_SOURCE returns to the CARRY_POSE.

Why this design matters

The right-bias keeps targets inside the right arm workspace during pelvis-frame conversion.

Observed values: HOVER_SOURCE exited around palm_dist = 0.127 m, DESCEND_SOURCE timed out around 0.123 m, and attachment occurred around 0.128 m, supporting the reacher accuracy floor discussion.

What is intentionally omitted

Additional geometry helpers and per-state timers for hover/descend/close-grip transitions.

10 — Walker/Reacher Composition common/controller.py

The controller composes the walker and reacher policies by constructing the walker observation and decoding its action into joint targets. 

def step(self) -> np.ndarray:
    lin_vel, ang_vel = self._get_base_velocities()
    proj_gravity = self._get_projected_gravity()
    joint_pos = self._get_joint_positions()
    joint_vel = self._get_joint_velocities()

    cmd = np.array(
        [self.lin_vel_x, self.lin_vel_y, self.ang_vel_z],
        dtype=np.float32,
    )

    obs = np.concatenate([
        lin_vel,
        ang_vel,
        proj_gravity,
        joint_pos,
        joint_vel,
        self.last_action,
        cmd,
    ]).astype(np.float32)

    action = self.walker_policy(obs)
    target_pos = self.default_joint_pos + action * self.action_scales

What this block does

Builds the 99D walker observation from:

  • base linear velocity
  • base angular velocity
  • projected gravity
  • joint positions
  • joint velocities
  • last action
  • command velocity

Why this design matters

The walker receives raw observations because the ONNX model already includes its own normalization.

What is intentionally omitted

The full joint index mapping and scale configuration stored in model_config.json.

13 — Kinematic Grasp Backend common/grasp.py

The kinematic backend fakes grasping by snapping and updating the object pose directly. 

class GraspBackend(ABC):
    @property
    @abstractmethod
    def attached(self) -> bool:
        ...

    @abstractmethod
    def tick(self, grip_closed: bool) -> bool:
        ...

    @abstractmethod
    def release(self) -> None:
        ...
ATTACH_DIST: float = 0.13
SNAP_DIST: float = 0.03

def tick(self, grip_closed: bool) -> bool:
    if not self._is_attached:
        if grip_closed:
            palm = self._data.site_xpos[self._palm_id].copy()
            obj = self._data.xpos[self._obj_id].copy()
            if float(np.linalg.norm(palm - obj)) <= self.ATTACH_DIST:
                self._attach(palm, obj)
    else:
        if not grip_closed:
            self._release()
        else:
            self._update_pose()
    return self._is_attached
def _attach(self, palm, obj) -> None:
    self._local_offset = obj - palm
    if np.linalg.norm(self._local_offset) < SNAP_DIST:
        self._local_offset = np.array([0.0, 0.0, SNAP_DIST])
    self._disable_collisions()
    self._is_attached = True

def _release(self) -> None:
    self._enable_collisions()
    self._is_attached = False
def _update_pose(self) -> None:
    palm_pos = self._data.site_xpos[self._palm_id].copy()
    palm_rot = self._data.site_xmat[self._palm_id].reshape(3, 3).copy()
    new_pos = palm_pos + palm_rot @ self._local_offset

    self._data.qpos[self._qposadr:self._qposadr + 3] = new_pos
    self._data.qpos[self._qposadr + 3:self._qposadr + 7] = [1.0, 0.0, 0.0, 0.0]
    self._data.qvel[self._qveladr:self._qveladr + 6] = 0.0

What this block does

Triggers attachment, snaps a local offset, disables collisions, zeroes velocity, and releases on command.

Why this design matters

This is not contact-rich grasping—it isolates a simulation-only shortcut behind a replaceable interface.

What is intentionally omitted

Body ID lookups, collision bitmasks, and the exact snap-offset tuning logic.

14 — ONNX Runtime Wrapper common/onnx_policy.py

ONNXPolicy keeps inference portable and predictable across machines. 

class ONNXPolicy:
    def __init__(self, model_path: str | Path):
        sess_options = ort.SessionOptions()
        sess_options.intra_op_num_threads = 1
        sess_options.inter_op_num_threads = 1
        self.session = ort.InferenceSession(
            str(model_path),
            sess_options,
            providers=["CPUExecutionProvider"],
        )
        self.input_name = self.session.get_inputs()[0].name
        self.output_name = self.session.get_outputs()[0].name

    def __call__(self, obs: np.ndarray) -> np.ndarray:
        if obs.ndim == 1:
            obs = obs.reshape(1, -1)
        obs = obs.astype(np.float32)
        return self.session.run(
            [self.output_name],
            {self.input_name: obs},
        )[0][0]

What this block does

Loads ONNX with CPUExecutionProvider, fixes intra/inter-op threads to 1, and reshapes 1D observations.

Why this design matters

CPU-only inference keeps the baseline portable, single-threading improves determinism, and the reshape keeps smoke tests simple.

What is intentionally omitted

Model file locations and the exact joint normalization baked into each ONNX model.
