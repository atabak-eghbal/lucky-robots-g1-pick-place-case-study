Architecture in one paragraph

run.py is the entry point. It loads a MuJoCo scene at 200 Hz (timestep=0.005), runs four ONNX models (walker 99D→29D, reacher 36D→7D, croucher, rotator), and applies their outputs via PD control at 50 Hz (4× decimation). All locomotion and reaching intelligence is in pre-trained ONNX policies; WalkerReacherController in common/controller.py assembles the observations and dispatches to the right model each tick. KinematicAttachment in common/grasp.py implements a physics shortcut — it teleports the cylinder to the palm every physics step when the grip is closed, avoiding the need for contact-force grasping. The FSM in policies/fsm_core.py sequences 12 states (SETTLE through DONE) by computing world-frame geometry from MuJoCo ground-truth data and issuing walk commands and reach targets each tick. policies/fsm.py is the 57-line glue layer that bridges FSMCore's immutable outputs into the controller's mutable command state.

Critical cross-file invariants

These constraints span multiple files. Violating any one of them produces a bug that is hard to localise because the symptom appears in a different file from the cause.

1 — Grasp tick must run at 200 Hz, not 50 Hz

KinematicAttachment.tick() must be called inside the decimation loop in run.py — after every mujoco.mj_step(). If called only at the outer 50 Hz rate, gravity accumulates 0.049 m/s of velocity in the attached body between ticks, causing a visible drift during carry.

2 — Walker observation must NOT be normalized before passing to ONNX

The walker ONNX model bakes its own input normalization (mean/std) inside the graph. Normalizing the 99D observation in Python before calling walker(obs) would double-normalize and cause an immediate fall. Raw sensor values must be passed directly.

3 — Reacher runs unconditionally every tick

The walker policy was trained with the right arm held in a specific carry pose. If the reacher is deactivated (even for one tick while walking), the arm falls into a different position, destabilising the walker. The reacher overlay must be active at all times — even when reach_active=False is passed by the FSM, the controller still runs the reacher to maintain the carry pose.

4 — _RELEASE_STATES must include OPEN_GRIP (Step 10 bugfix)

FSMPolicy._close_grip_command() guards against accidental grip opening during carry. If FSMState.OPEN_GRIP is not in _RELEASE_STATES, the guard overrides the FSM's intentional grip_closed=False and the cylinder never releases. This was the critical Step 10 bug — the fix is adding FSMState.OPEN_GRIP to the frozen set.

5 — Target drop point must be frozen at APPROACH_TARGET entry

FSMCore._target_drop_pt is computed once when entering APPROACH_TARGET and never updated. If it were recomputed each tick, the drop position would drift as the robot walks toward the table — the cylinder would be released in a different position than intended.

6 — Reach targets are in pelvis frame; geometry is in world frame

FSMCore computes all geometry (cylinder position, table surface) in world frame using data.xpos[]. Reach targets are then converted to pelvis frame via _world_to_pelvis() before writing to ctrl.reach_target. Confusing frames produces a reach that looks correct in logs but misses the target in the simulator.

Suggested reading order

If you're new to this codebase, this order builds context progressively:

  1. policies/base.py — understand the PolicyOutput data contract first (3 min)
  2. common/onnx_policy.py — the ONNX inference wrapper used by all four models (5 min)
  3. common/scene.py — scene reset and camera helpers (5 min)
  4. common/grasp.py — KinematicAttachment physics shortcut (15 min)
  5. common/controller.py — walker/reacher composition and observation assembly (30 min)
  6. run.py — the simulation loop that ties everything together (20 min)
  7. policies/fsm_core.py — the 750-line autonomous state machine (45 min)
  8. policies/fsm.py — the adapter layer and grip-safety guard (10 min)
  9. scripts/smoke_env.py — what the pre-flight checklist validates (10 min)
  10. scripts/test_fsm_approach.py — the integration test harness (10 min)

Runtime

run.py

Entry point. Loads scene, sets armature, wires four ONNX policies, controller, FSM or keyboard policy, grasp backend, optional camera renderer. Runs the 200 Hz / 50 Hz decimated simulation loop.

common/

Shared simulation helpers

  • controller.py — 397-line controller. Walker/reacher ONNX dispatch, 99D and 36D observation assembly, arm overlay, PD control, finger commands. Key: reacher runs unconditionally.
  • grasp.py — KinematicAttachment: teleports cylinder to palm every physics step, disables cylinder collisions on attach, zeroes velocity to cancel gravity drift.
  • onnx_policy.py — 34-line CPU ONNX wrapper. Enforces single-threaded deterministic inference. Used by all four models.
  • scene.py — Deterministic robot reset from config joint positions. Offscreen CameraRenderer.
policies/

Decision making

  • base.py — PolicyOutput frozen dataclass (walk_cmd, reach_target, reach_active, grip_closed). BasePolicy ABC.
  • keyboard.py — Manual control path as a BasePolicy subclass. Preserved for regression testing.
  • fsm.py — 57-line adapter. Runs FSMCore.tick(), applies grip-safety guard, writes commands into controller. Contains the Step 10 OPEN_GRIP bugfix.
  • fsm_core.py — 748-line autonomous brain. 12-state machine, world-frame geometry, pelvis-frame reach conversion, staircase velocity schedule, all timeouts and debounce counters.
scripts/

Validation runners

  • smoke_env.py — 231-line pre-flight checklist. Validates config, scene, 5 cameras, 4 bodies, 4 sites, all joints, and ONNX warmup for required models. Exits 0 on full pass.
  • test_fsm_approach.py — 130-line headless integration test. Runs full pipeline (walker + reacher + FSM + grasp) for up to 3000 ticks (60 s), checks cylinder landed on target table.
