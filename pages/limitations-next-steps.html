Tier 1 — Headless-validated ✓ Verified

The claims below were confirmed by code that runs without a rendered display and returns a verifiable result. They can be re-run and checked automatically.

  • Scene and asset loading. Named MuJoCo bodies, sites, cameras, joints, and both ONNX policies all load and pass the smoke-test assertions (scripts/smoke_env.py).
  • ONNX observation contract. The walker policy applies internal normalization. Raw-zero input produces a maximum action of 0.628; normalized-zero input produces 14.78. External normalization must not be added.
  • Kinematic attach parameters. The development log records an observed attach distance of 0.128 m with snap_offset = 0.030 m. These values were confirmed at runtime by the grasp backend, not inferred.
  • Control-loop rate. timestep = 0.005 s with decimation = 4 gives 200 Hz physics and 50 Hz control. The APPROACH_TARGET timeout of 900 control ticks equals 18 s at this rate.

Tier 2 — Reference-run visual inspection ◎ Visually verified

The behaviors below were observed in a single rendered MuJoCo reference run during development. They confirm that the described code paths execute and produce the expected motion at least once, under the conditions of that specific run.

These observations do not constitute repeated-trial confirmation and cannot be treated as success-rate evidence. Each carries the caveats described.

  • Source approach and reach corridor entry. The robot entered the source-side reach corridor and the FSM advanced to HOVER_SOURCE. Relies on a ground-truth cylinder-pose lookup; Visual Oracle integration is future work.
  • Hover and descend. The palm approached the hover target (table + 0.18 m) and grasp target (table + 0.06 m). The reacher accuracy floor (~0.12–0.13 m) means the palm does not reach the geometric center of the cylinder; attachment is designed to trigger at this floor.
  • Lift and carry. The attached cylinder tracked the palm through the lift phase. Carry-pose stability was not quantified.
  • Target transport with compound approach guard. The robot navigated to the target table after the false-positive guard (body ≤ 0.24 m, yaw ≤ 0.40 rad) was added. Navigation parameters were tuned empirically for this scene.
  • Placement and release. The FSM lowered, opened the grip, detached, and retracted. The cylinder appeared to rest on the target table. Post-release settling was not confirmed by any proximity or contact sensor check.

Tier 3 — Known gaps and future validation work ○ Proposed

The following are limitations of the current submission that have not been addressed and require explicit future work before stronger claims can be made.

  • No post-DONE on-table confirmation. The DONE state is terminal; there is no programmatic check that the cylinder rests on the target table after release. Placement success rests entirely on the single visual observation noted in Tier 2.
  • Kinematic grasping is a simulation shortcut. The attach/detach mechanism bypasses contact dynamics, finger forces, and slip. It is not a proxy for physical manipulation quality.
  • Visual Oracle is architectural design only. The source localization pipeline (RGB segmentation, depth back-projection, EMA smoothing, freeze logic) is fully specified but the implementation files (vision/observer.py, vision/geometry.py, policies/fsm_visual_oracle.py) are not part of this submission. All source-side phases currently use a ground-truth simulation state read.
  • Target-table success is not robustly validated. Navigation to the target table succeeded once under the reference-run conditions. Reproducibility across varied robot starts, object positions, or scene perturbations is unknown.
  • Target-side pose precision is unmeasured. The reacher accuracy floor that affects source grasping applies equally to the HOVER_TARGET and LOWER_TARGET phases. Drop-point offset on the target table was not measured.
  • Wrist camera not used. The wrist-mounted camera is available in the scene but is not read in the current baseline.
  • Sim-to-real gap is uncharacterized. No domain randomization, sensor noise injection, or hardware testing has been attempted.

Prioritized next steps

Ordered roughly by how much evidence each step would add relative to the gaps above.

  1. Add a post-DONE ground-truth proximity check to confirm on-table placement programmatically and retire the visual-only placement claim.
  2. Run the FSM headlessly across multiple seeds and record the terminal state, producing a first success-rate estimate.
  3. Implement the Visual Oracle pipeline and replace the ground-truth source localization with the observer output; validate with the existing headless runner.
  4. Log palm-to-target error during HOVER_TARGET and LOWER_TARGET to characterize placement precision on the target side.
  5. Add contact-aware grasping with slip detection to replace the kinematic attachment shortcut.
  6. Apply domain randomization and sensor noise; expand dashboards for timing, failure recovery, and pose drift metrics.
