Recording objective

The video should feel like a short design review. Start with the best simulation clip, then explain the decomposition, implementation decisions, evidence, caveats, and future work.

Important: Do not describe the system as production-ready, robust, or hardware-ready. The accurate claim is that this is a simulation-only GT FSM baseline with visually successful final placement and known validation caveats.

Recommended timeline

Time On screen Message
0:00–0:15 Best full-run clip Show the result first. Say this is a modular simulation baseline.
0:15–0:50 Challenge page Frame the task: move the red cylinder from the source table to the target table.
0:50–1:40 Architecture page Explain runtime, controller, FSM, grasp backend, and future perception layer.
1:40–2:50 Lessons page Explain the double-normalization bug, always-on reacher, and reacher accuracy floor.
2:50–4:20 Implementation deep dive Show run.py, common/controller.py, common/grasp.py, and policies/fsm_core.py.
4:20–5:40 Results page Explain verified vs visually verified vs future/proposed outcomes.
5:40–6:30 Failure analysis Explain the target-side false positive and why world-proximity/yaw gating was added.
6:30–7:30 Limitations and references Explain future perception, post-release validation, physical grasping, and learned-policy comparisons.
7:30–8:00 Home page or final clip Close with the value: a debuggable baseline where each subsystem can be upgraded independently.

Closing line

"The main value of this work is not that it hides the hard parts. It establishes a traceable autonomy baseline where locomotion, reaching, grasping, placement validation, and future perception can each be improved independently."
